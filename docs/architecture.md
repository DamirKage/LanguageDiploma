# Архитектура

## Обзор

```
client (React 19 + TypeScript + Vite)         server (Node.js 24 + Express 5)              MongoDB 8
 ├─ React Router 7, TanStack Query  ── REST ──► ├─ zod: валидация + OpenAPI 3.1  ───────────► 19 коллекций
 ├─ axios: access-токен в памяти               ├─ JWT (HS256) + refresh в httpOnly-cookie
 ├─ Chart.js (react-chartjs-2)                 ├─ модули: auth, users, catalog, learning,
 ├─ Web Speech API: озвучка, распознавание    │    srs, recommendations, analytics, admin
 └─ i18n: словари интерфейса (ru)              └─ интеграции: Wiktionary REST, SMTP (nodemailer)
                           shared (@linguapath/shared): типы DTO, константы, контракты упражнений
```

Монорепозиторий на npm workspaces: `shared`, `server`, `client`. Общие типы подключаются как исходники TypeScript. Vite и tsx компилируют их сами, а tsup встраивает их в сборку сервера.

## Сервер

| Модуль | Ответственность |
|---|---|
| `lib/http.ts` | Обёртка над Express Router: валидация `params/query/body` через zod, единый формат ответа, регистрация маршрута в OpenAPI |
| `modules/auth` | Регистрация, вход, ротация refresh-токенов, восстановление пароля, middleware ролей |
| `modules/users` | Профиль, языки (enrollments), смена пароля, удаление аккаунта со всеми данными |
| `modules/catalog` | Языки, темы, учебный путь, уроки без ответов, словарь, справка Wiktionary |
| `modules/learning` | Попытки (урок, тест, практика, входной тест), проверка ответов, итоги |
| `modules/srs` | SM-2, очередь повторения, ответы на карточки |
| `modules/recommendations` | Снимок учащегося, движок, план дня, симуляция |
| `modules/analytics` | Сводка, динамика, темы, ошибки, повторение |
| `modules/admin` | CRUD контента, медиафайлы, пользователи, агрегированная статистика |

Ошибки формируются централизованно (`AppError` → `{ error: { code, message, details } }`). Код ошибки стабилен, клиент переводит его сам, а сообщение служит русским резервным текстом без внутренних подробностей. Сообщения валидации zod выводятся на русском (`z.locales.ru()`).

## Безопасность

- Пароли хешируются bcrypt (`bcryptjs`, стоимость 12 по умолчанию, настраивается). При неизвестном адресе выполняется такое же по времени сравнение с фиктивным хешем, поэтому по времени ответа нельзя понять, существует ли аккаунт.
- Access-токен (JWT HS256, 15 минут) передаётся в заголовке `Authorization` и хранится только в памяти клиента — не в `localStorage`.
- Refresh-токен — случайные 48 байт. В базе хранится только SHA-256 хеш. Cookie: `httpOnly`, `SameSite=Strict`, `Path=/api/auth`, `Secure` в продакшене.
- Ротация refresh-токенов с обнаружением повторного использования. Если уже использованный токен предъявлен позже чем через 10 секунд, отзывается всё «семейство» токенов. Окно в 10 секунд допускает одновременное обновление из двух вкладок.
- CSRF: эндпоинты, работающие по cookie (`/auth/refresh`, `/auth/logout`), требуют заголовок `X-Requested-With: linguapath`. Браузер не отправит его кросс-доменно без CORS preflight, а CORS разрешён только для `CLIENT_ORIGIN`. Остальные эндпоинты используют Bearer-токен и CSRF не подвержены.
- При каждом запросе пользователь перечитывается из базы, поэтому удаление аккаунта действует сразу; роль администратора назначается только при развёртывании (скрипт `seed`), а не через интерфейс.
- Rate limiting: 30 запросов за 15 минут на эндпоинты аутентификации, 1500 — на API в целом.
- `helmet` (CSP и другие заголовки), ограничение тела запроса 1 МБ, строгая типизация входа через zod. Это исключает внедрение операторов MongoDB: в фильтры попадают только строки и числа.
- Владение данными: попытки, повторение, аналитика и план всегда фильтруются по `user`. Чужая попытка возвращает 404, а не 403, чтобы не раскрывать факт существования.
- Загрузка файлов: белый список MIME-типов, проверка сигнатуры содержимого, случайное имя файла, `X-Content-Type-Options: nosniff`.
- Восстановление пароля: одноразовый токен на 1 час, хранится хеш. Ответ не зависит от существования аккаунта, после смены пароля завершаются все сессии.
- Удаление аккаунта удаляет все учебные данные пользователя.
- Администратор видит только агрегаты. Рейтинги сложных тем и заданий строятся при наличии данных минимум от 3 учащихся.

## Модель данных (MongoDB)

| Коллекция | Назначение | Ключевые индексы |
|---|---|---|
| `users` | Аккаунт, роль, часовой пояс, бюджет времени, цели, активный язык | `email` unique, `role` |
| `enrollments` | Изучаемые языки и текущий уровень, результат входного теста | `{user, language}` unique |
| `refreshtokens` | Хеши refresh-токенов, семейство, использование, отзыв | `tokenHash` unique, TTL по `expiresAt` |
| `passwordresettokens` | Хеши токенов восстановления | `tokenHash` unique, TTL |
| `languages` | Язык: название, самоназвание, локаль озвучки, особые символы | `code` unique |
| `topics` | Справочник тем (грамматика, лексика, коммуникация) | `key` unique |
| `courses` | Язык × уровень CEFR | `{language, level}` unique |
| `modules` | Модули курса | `course`, `{language, level, order}` |
| `lessons` | Цель, теория, слова, задания (встроенные), предпосылки | `key` unique, `module`, `exercises.key` |
| `words` | Слово, перевод, часть речи, род, пример, аудио/изображение | `{language, term}` unique, `{language, topic}` |
| `tests` | Входные, модульные и тесты уроков | `{language, kind}`, `module`, `lesson` |
| `attempts` | Попытка: снимок заданий, ответы, вердикты, результат | `{user, status, kind, lesson}`, `{user, language, completedAt}` |
| `answerevents` | Каждый ответ: тема, навык, категория, вердикт, время | `{user, language, at}`, `{user, language, topic, at}`, `{language, exerciseKey}` |
| `lessonprogresses` | Статус урока, лучший и последний результат | `{user, lesson}` unique |
| `reviewitems` | Состояние SM-2 по слову | `{user, word}` unique, `{user, language, dueAt}` |
| `reviewlogs` | Журнал повторений (качество, интервалы, просрочка) | `{user, language, at}` |
| `recommendationsnapshots` | Выданные рекомендации, признаки, принятые ключи | `{user, language, generatedAt}` |
| `dailyplans` | План на локальный день | `{user, language, date}` unique |
| `dictionarycaches` | Кэш Wiktionary | `key` unique, TTL 7 дней |

Решения:

- Задания встроены в урок: урок редактируется и публикуется целиком, а попытка хранит снимок заданий. Поэтому последующие правки контента не переписывают историю.
- `answerevents` — единственный источник для точности и анализа ошибок. Аналитика и рекомендации считают одно и то же одинаково.
- Целостность ссылок проверяется на уровне приложения: удалить язык с курсами, курс с модулями или модуль с уроками нельзя. При удалении урока снимаются ссылки предпосылок, при удалении слова оно убирается из уроков и повторения. Ключи заданий уникальны во всём каталоге.

## Учебный контент

Пять языков по 19 уроков (A1: 5, A2: 4, B1: 3, B2: 3, C1: 4), всего 95 уроков. Уровень C1 добавлен сверх ТЗ (в ТЗ — A1–B2) по решению владельца проекта.

- 1001 задание одиннадцати типов: выбор ответа (178), заполнение пропуска (180), перевод (177), порядок слов (68), диалог (66), аудирование (48), произношение (54) и интерактивные — переписка (65), найдите ошибку (60), текст с пропусками (60), разложите по группам (45). В каждом уроке A1–B2 есть по два интерактивных задания, в каждом уроке C1 — все четыре;
- 665 слов с переводом, частью речи и примером;
- 5 адаптивных входных тестов по 40 заданий (по 8 на уровень);
- 95 контрольных тестов уроков по 5 собственных вопросов и итоговые тесты модулей.

Многосоставные задания (текст с пропусками, переписка, группы) оцениваются частично: всё верно — 10 баллов, верно не меньше двух третей частей — «почти верно» (7 баллов). В разборе ответа отмечается, какие части верны.

Каждая тема задания сверяется со справочником тем при загрузке контента и при сохранении через админ-панель.

Контент — учебные материалы, написанные для демонстрации, с пояснениями на русском. Экспертизу преподавателей и методистов он не проходил, проверка носителями языка рекомендуется до использования с реальными учащимися. Особенно это касается казахского и турецкого.

Контент хранится в `server/src/seed/content/*.ts` в компактном формате. Скрипт `seed` проверяет каждое задание той же zod-схемой, что и админ-панель, и загружает контент идемпотентно по стабильным ключам, поэтому повторный запуск не ломает прогресс пользователей. Демо-учащиеся (`isDemo: true`) получают историю, сгенерированную через те же сервисы, что используются в реальном обучении.

## Проверка ответов

`modules/learning/checker.ts`:

- **Строгое сравнение:** без учёта регистра, пунктуации и пробелов. Учитываются локали (турецкие İ/ı), немецкие эквиваленты (ä = ae, ß = ss), английские сокращения (I'm = I am) и ё = е для русских ответов.
- **«Почти верно» (7 баллов из 10):**
  - совпадение без диакритики;
  - казахские буквы, набранные русскими (отдельная подсказка);
  - одна опечатка в длинном слове — но только если последние две буквы совпадают: окончания несут грамматику, и ошибки в них не прощаются.
- **Произношение:** сходство распознанного текста с эталоном: от 0,85 — верно, от 0,6 — почти верно. Если распознавание недоступно, задание заменяется письменным: фраза скрыта, учащийся слушает её (или видит перевод) и пишет по памяти; такой ответ проверяется как текстовый.
- **Варианты для выбора в пропуске:** только точное совпадение.

## Интеграции

- **Озвучка:** порядок источников — запись, загруженная администратором; заранее подготовленная запись фразы (`client/public/audio/<язык>/manifest.json`, см. `docs/audio.md`); синтез речи браузера (`speechSynthesis`). Распознавание речи через `SpeechRecognition` — экспериментальная функция; если оно недоступно, это прямо сообщается и предлагается альтернативное письменное задание (или пропуск без штрафа).
- **Wiktionary REST API:** определения на английском для всех пяти языков, кэш на 7 дней. Если сервис недоступен, возвращается 503 с понятным сообщением. Из среды разработки внешний доступ был закрыт, поэтому проверены разбор ответа (модульный тест) и обработка ошибки, но не живой запрос.
- **SMTP (nodemailer):** письма восстановления пароля. Если `SMTP_URL` не задан, письмо не отправляется. В режиме разработки (`EXPOSE_DEV_LINKS=true`) ссылка показывается в интерфейсе с явной пометкой; в продакшене этот режим запрещён конфигурацией.

## Клиент

- Маршрутизация: публичные страницы, онбординг, «фокус-режим» (плеер занятия и повторение без навигации), основное приложение, админ-панель. Страницы загружаются лениво.
- Данные с сервера идут через TanStack Query. После любого учебного действия инвалидируются ключи плана, рекомендаций, пути, аналитики и повторения.
- Локализация: `src/i18n` — типизированный словарь `ru`. Новая локаль — это объект того же типа `Messages`, проверяемый TypeScript. Плюральные формы берутся из `Intl.PluralRules`, даты и числа форматирует `Intl`. Учебный контент хранится как `LocalizedText` (`{ ru: …, … }`), поэтому переводы для других языков интерфейса добавляются в данные без изменения кода.
- Доступность: связанные `label` и `aria-describedby`, роли `radiogroup` и `radio` для вариантов ответа, управление с клавиатуры (цифры для вариантов, Enter — проверить или дальше), ссылка «Перейти к содержимому», видимые фокусы, `aria-live` для обратной связи.
- Адаптивность: боковая навигация на десктопе, нижняя панель вкладок на телефоне. Проверено на 1440×900 и 390×844, отсутствие горизонтальной прокрутки на 390 px проверяется сквозным тестом.
- Плеер занятия: задание и разбор ответа в одной колонке, рядом — тема и навык задания с пометкой, что ответ учитывается в аналитике. Ошибки не повторяются внутри урока, а попадают в персональный план как практика слабой темы.
- Анимации (`client/src/styles/motion.css`, `client/src/components/motion`) несут смысл: караоке-подсветка слов во время воспроизведения (позиция берётся из записи или из событий синтеза речи, общее состояние — `lib/playback.ts`), круговой визуализатор реального сигнала записи через Web Audio `AnalyserNode`, перелёт плиток в задании «порядок слов» (FLIP через Web Animations API), «отказ» неверного варианта и блик по верному, шкала уровня с маркером в итогах входного теста, отсчёт процента, каскадное появление списков, «расшифровка» приветствия буквами пяти алфавитов и рисующийся маршрут между языками на главной. При системной настройке «уменьшить движение» анимации отключаются.
- Темы оформления: «Ночь» (по умолчанию), «День», «Бумага» и «Как в системе». Это наборы значений одних и тех же CSS-токенов (`client/src/styles/tokens.css`); выбор хранится в `localStorage` и применяется до отрисовки страницы (`client/src/lib/theme.ts`). Все темы проверены на контрастность WCAG AA.

## Режим демонстрации

`npm run demo` (`server/src/demo.ts`) собирает клиент и запускает всё в одном процессе на `http://localhost:8080`: встроенная MongoDB (`mongodb-memory-server`, данные в папке `demo-data`), API и статические файлы клиента. При первом запуске загружаются курсы и демо-аккаунты. Ключ JWT генерируется и сохраняется в `demo-data/secret`. Режим предназначен для проверки на одном компьютере без MongoDB и Docker; для развёртывания используется `docker compose`.
